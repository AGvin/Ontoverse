# Моделі

Статус: чернетка

Цей розділ містить концептуальні моделі ширшого фреймворку Ontoverse.

Кожна модель має залишатися сфокусованою, явно позначати свій спекулятивний статус і показувати відкриті завдання формалізації.

## Поточні моделі

- [`history-space/`](../../sub/history-space/l10n/uk_UA/) — моделює простір історій як стиснений пучок поточно розрізнюваних класів еквівалентності, з історичними жилами, розгалуженням у першій необхідній відмінності, сумісністю, конвергенцією та доступом спостерігача.
- [`frontal-time/`](../../sub/frontal-time/l10n/uk_UA/) — моделює фронтальний час як глобальну послідовність або сімейство зрізів пучка `S(F)`, де класи розділяються через необхідні відмінності стану, а локальне накопичення часу описується через темпоральну щільність і окреме поняття щільності причинної обробки.
- [`event-density-dark-sector/`](../../sub/event-density-dark-sector/l10n/uk_UA/) — досліджує, чи можуть деякі темно-матерієподібні ефекти відповідати ефективному метричному внеску прихованих структур причинної обробки та їхньому впливу на локальну частоту переходів.
- [`closed-time-loop/`](../../sub/closed-time-loop/l10n/uk_UA/) — досліджує глобально самоузгоджену подорож у минуле в пучку історій, включно з розділенням класу під час реінтеграції, відсутністю створення гілки в точці відправлення, ізоляцією транзиту, інформацією з майбутнього та компенсацією параметрично збагаченого інтервалу.

## Спільні структурні терміни

Поточний набір моделей використовує такі розрізнення:

```text
простір історій
-> допустимі повні історії

пучок історій
-> поточно представлені розрізнювані класи історій

історична жила
-> представлення одного поточного класу еквівалентності історій

зріз фронтального часу S(F)
-> глобальний поперечний зріз представленого пучка

вузол розгалуження
-> перша значуща точка, де клас уже потребує різних описів поточного стану
```

## Рівні статусу моделей

За потреби використовуйте такі позначки:

- `чернетка` — раннє концептуальне формулювання;
- `робоче визначення` — термінологія вже придатна до використання, але може змінитися;
- `стабільна концепція` — термінологія достатньо стабільна для повторного використання в документації;
- `відкрите питання` — нерозв’язане питання, що потребує формалізації або зовнішнього порівняння;
- `відкрите завдання формалізації` — спекулятивний концептуальний місток, який потребує математичного визначення, порівняння з наявними теоріями та зовнішніх обмежень, перш ніж його можна буде оцінювати.

## Правило написання

Не подавайте спекулятивні компоненти моделей як усталену фізику.

Коли модель торкається відомої фізики, розділяйте:

- усталену концепцію;
- інтерпретацію Ontoverse;
- спекулятивну гіпотезу;
- нерозв’язану проблему.
