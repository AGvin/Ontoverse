# Для дослідників і наукових комунікаторів

Статус: чернетка

Ontoverse може бути цікавим як приклад побудови преформального фреймворку: як незалежний автор упорядковує концептуальні інтуїції, аналогії, термінологію та спекулятивні структури до того, як вони отримають математичну формалізацію або будуть відкинуті.

Проєкт не подається як доказ. Це матеріал для перевірки, критики, порівняння та можливої формалізації.

## Що таке Ontoverse

Ontoverse — самостійно розроблений концептуальний фреймворк для організації уявлень про реальність, концепції та можливі приховані зв’язки між ними.

Він структурований як дослідницький блокнот, що містить:

- визначення;
- концептуальні моделі;
- діаграми;
- гіпотези;
- аналогії;
- відкриті проблеми;
- порівняння з наявними науковими та філософськими концепціями.

## Чим Ontoverse не є

Наразі Ontoverse не заявляється як:

- завершена фізична теорія;
- заміна квантової механіки чи теорії відносності;
- доказ прихованих змінних;
- доказ багатосвітової або будь-якої іншої інтерпретації;
- новий експериментально підтверджений закон;
- містичне або одкровенне твердження.

## Корисні питання для рецензування

Продуктивний розгляд Ontoverse має запитувати:

- Що потрібно визначити математично?
- Які терміни дублюють уже наявні поняття?
- Які аналогії корисні, а які вводять в оману?
- Які частини можна відкинути одразу?
- Які частини є лише схемами найменування?
- Які частини містять потенційно корисну абстракцію?
- Яка наявна література найближча до кожної ідеї?
- Що могло б вважатися відмінним передбаченням, якщо воно взагалі є?

## Комунікаційний кут

Безпечна публічна подача — не «хтось довів нову теорію».

Краще питання:

```text
Чи може самостійно розроблений концептуальний фреймворк виявити корисну структуру
ще до того, як наука має для неї формальну назву?
```

Або:

```text
Як спекулятивні інтуїції перетворюються на ідеї,
які можна перевіряти, критикувати й зрештою формалізувати?
```

## Бажана критична позиція

До Ontoverse слід підходити з конструктивним скептицизмом.

Мета не в тому, щоб захищати кожен термін, а в тому, щоб розділити:

- корисні абстракції;
- оманливі аналогії;
- термінологію, яку варто перейменувати;
- ідеї, уже охоплені наявними дисциплінами;
- нерозв’язані частини, що потребують формальної роботи;
- частини, які слід відкинути.
